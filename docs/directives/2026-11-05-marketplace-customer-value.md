# Marketplace customer value directive

The founder requires every Marketplace increment to improve customer acquisition, time saved, earnings/cost transparency, trust/reliability or sustainable growth/retention. Native listing upload alone is not success. Ghana is the first pilot, not a permanent geographic limit. Core registration, listing, access and EcoVibes commissions remain GH₵0.

Current dependency-ready assignment: category/attribute validation on existing products before Request Market. Preserve existing data and shared commerce services. No parallel order engine, fake matches, seeded traction, unsupported verification badges, paid activation or production release without approval.

Demand matching must eventually reuse Chale/search/authorized location, actual inventory or confirmed sourcing, eligible merchants, quotations and accepted-offer-to-order commands. Empty search must lead to actionable buying requests only after that real service exists. Pickup/tracking, installation/repair, recycling, Product Vault, Circles and Africa Trade activate only when underlying services pass their gates.

Optimize for ordinary traders, low-end Android, variable connections, selected-file access, low data, clear GHS price/unit and pickup/fulfillment disclosures. Approved mobile-money, language and assisted-support acceptance remain separate work; no live-support or delivery promise is invented.

Measure seller activation/time to first listing, inquiry conversion, seller inquiries, offer acceptance, completed orders/fulfillment, complaints/resolution, repeat buyers, retention and cost per fulfilled order from genuine authorized records. This increment has synthetic acceptance evidence, not customer acquisition or earnings evidence. Do not treat fixtures as traction.
