Implemented:
- An account-owned cart uses canonical product/variant IDs, saved quantities and optimistic revisions. Device preview items remain separately labelled and are never silently converted.
- New GET/PUT /api/v1/marketplace/cart and POST /api/v1/marketplace/cart/checkout reuse the existing order writer. Immutable actor/client-key commands plus one-command-per-cart-revision prevent duplicate reservations and orders. Retrying an acknowledged or lost-response request returns the original order and preserves later cart items.
- Canonical item-price fingerprints and totals are reviewed again while product locks are held, including price changes that offset in the aggregate total. Existing integer database limits are respected. No payment/provider operation occurs; successful orders are unpaid and existing fulfillment/payment/expiry services remain separate.
- Current app session/CSRF, active actor and active seller are checked inside the cart transaction. Cached commands cannot bypass app-session revocation. This does not close the separate Supabase recovery/global-revocation gate in PR24.
- The signed-in Bag has a real catalog/quantity/review flow. The existing account catalog routes ordering to this review. Ownership echoes, account switching, aborted/late requests, request/body deadlines, offline controls and honest unknown outcomes are handled. Optional roles are not required for core personal access.
